# S1-8B / S1-8C JSON 与工程资源限制校准状态

状态：**部分防护已实现；任务未验收；限制值待标定**

## 已落地的临时解析器防护

`core/src/json.cpp` 当前设置了以下开发期硬上限：

| 防护 | 当前临时值 | 目的 |
|---|---:|---|
| JSON 输入字节 | 64 MiB | 防止任意大输入直接进入解析器 |
| 嵌套深度 | 64 层 | 限制递归栈深度 |
| 单个字符串/对象键 | 4 MiB | 限制单值分配 |
| 单容器成员数 | 100,000 | 限制单个数组/对象的元素数 |
| JSON 值节点总数 | 500,000 | 限制解析树总体规模 |

这些数值是**临时防御性护栏，不是已标定的产品规格**。代码注释已明确这一点。不能据此宣称S1-8B或S1-8C完成。

## 已新增的解析器测试

- 65层嵌套被拒绝
- 当前配置边界64层可接受
- 超过4 MiB字符串被拒绝
- 超过单容器元素上限的数组被拒绝

以上测试已写入 `tests/test_json.cpp`，**尚未执行**。

## 尚缺的验收证据

任务主文档明确要求：限制值必须结合真实工程样本、目标手机内存预算、Parser能力和压力测试标定；没有真实工程样本时，限制值保持待标定。

当前仓库中尚未找到可作为产品真实工程基线的 `.nclip` 样本。现有 `tests/test_serialization.cpp` 样本为合成单元测试数据，不能代表真实用户工程的轨道、片段、关键帧、字幕、特效、代理记录规模。

因此目前不能确定：
- 真实工程的文件大小分布及高分位数
- assets / sequences / tracks / clips / keyframes / subtitles 等实体规模上限
- 目标手机解析峰值内存、耗时及OOM边界
- JSON节点数、字符串长度、数组数量的合理产品阈值
- 工程尺寸、媒体元数据和渲染资源预算的最终上限

## 下一步验收条件

1. 取得脱敏真实 `.nclip` 工程样本，覆盖常规工程和大型工程。
2. 在目标 Android 设备上记录文件大小、实体数量、解析耗时和峰值内存。
3. 对样本逐步放大实体规模并执行压力/边界测试，确定阈值及安全余量。
4. 再把临时值调整为有证据的正式值，并验证合法样本不被误拒。
5. 在反序列化层增加工程实体计数、尺寸/乘法溢出、资源预算校验；失败时确保目标Project不被部分污染。
6. 完成畸形、超深、超大、超限、内存压力及半加载失败测试后，才可验收S1-8B/8C。
