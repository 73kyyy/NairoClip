# NairoClip 变换参数规范（跨平台）

**状态：当前 ClipTransform 规范；适用于 Android、iOS、桌面端的同一引擎语义。**

本规范定义片段画面变换的单位、数值边界和交互策略。各平台可以采用不同控件，但不得改变同一属性的单位、正负方向、默认值或硬边界。滑块和数值输入使用完全相同的引擎硬范围；滑块用于粗略定位，数值输入用于同一范围内的精细定位。

## 1. 规范参数

| 属性 | 引擎硬范围 | 滑块范围 | 数值输入范围 | 单位 / 语义 |
|---|---:|---:|---:|---|
| X | -10..10 | -10..10 | -10..10 | 归一化画布宽度；1 = 向右移动一个画布宽度 |
| Y | -10..10 | -10..10 | -10..10 | 归一化画布高度；1 = 向下移动一个画布高度 |
| Scale | 0.05..10.0 | 5%..1000% | 5%..1000% | UI 百分比；引擎倍率 = 百分比 / 100；100% 为 1.0 |
| Rotation | -3600..3600° | -3600..3600° | -3600..3600° | 度；正值顺时针；保留整圈数，不自动折返 |
| Anchor | 0..8 | 九宫格选择 | 九宫格选择 | 缩放与旋转的共同枢轴；默认 4 |

## 2. 锚点索引

| 索引 | 位置 | 索引 | 位置 | 索引 | 位置 |
|---:|---|---:|---|---:|---|
| 0 | 左上 | 1 | 上中 | 2 | 右上 |
| 3 | 左中 | 4 | 中心 | 5 | 右中 |
| 6 | 左下 | 7 | 下中 | 8 | 右下 |

九宫格是快捷预设，不等于自由坐标锚点。自由锚点需要独立的版本化数据模型、序列化字段、C ABI 和预览/导出一致性迁移，不得通过把九宫格索引伪装成坐标来实现。

## 3. 交互要求

1. 滑块和数值输入必须使用完全相同的最小值、最大值，且与引擎硬范围一致。
2. 滑块用于粗略、连续地接近目标值；数值输入用于在相同范围内精细设定，不得提供滑块无法到达的额外范围。
3. 滑块范围固定，不得随当前值或拖动过程动态变化；数值输入在确认时校验并限制到同一范围，无效输入不得写入引擎。
4. X/Y 必须标明归一化画布单位；缩放必须标明百分比及 100% 基准；旋转必须显示度数且保留多圈角度。
5. 锚点选择必须显示当前选中位置，并通过同一变换命令写入；Android 使用单一 `selectableGroup` 包含九个 `RadioButton` 语义选项，TalkBack/VoiceOver/桌面辅助技术应能读出九个位置及选中状态。
6. 拖动期间可更新本地草稿，手势结束时提交一次可撤销命令，避免每个指针采样点都产生撤销记录。
7. 所有平台的静态变换、关键帧、预览与导出必须遵循相同单位和硬边界。


## 4. 关键帧插值语义

1. 变换关键帧写入时必须按对应属性的统一硬范围校验；旋转关键帧允许保留完整角度值（例如 0°、360°、720°），不得在写入或采样时对 360° 取模。
2. 旋转采用数值域直接插值。0° → 720° 的中间时刻应经过 360°，表示两整圈；若用户需要反向旋转，应通过关键帧值明确表达方向，不由引擎擅自选择最短角路径。
3. 位置、缩放、旋转等通道在缓动曲线计算后，采样结果仍必须钳制到各自的统一硬范围。贝塞尔 Y 控制点允许产生过冲，但过冲不能把最终属性值带出引擎允许范围。
4. 关键帧端点、区间外采样和区间内插值都必须保持同一范围语义；无效非有限数值不得传播到渲染矩阵。

## 5. 跨功能复用规则

本表是 **ClipTransform** 的规范。其它效果（例如几何效果栈中的 Offset、Stretch、Spin）如果具有不同的物理含义或归一化方式，必须在其功能契约中明确单位、常用范围、精确输入范围和硬边界；不得只因名称同为 X/Y/Scale/Rotation 就盲目套用 ClipTransform 的数值。若它表达的是同一种画面位置、缩放或旋转属性，则必须复用本规范或在边界层做明确、可测试的单位转换。

当前 `XformParams` 的效果栈有独立语义：`value` 是效果强度（0..2），`angle/phase` 使用弧度并归一化到一个完整圆周，`freq` 是频率，`anchor` 与 `ClipTransform` 共用同一九宫格索引（0..8，中心 4）。因此，效果栈的角度不能直接套用 ClipTransform 的度数边界；只有确实表示片段画面旋转的属性才使用 `-3600°..3600°`。所有浮点参数必须在进入渲染矩阵前完成有限值处理，不能让 NaN/Infinity 传播到仿射计算。`XformParams::clamp()` 对非有限值采用确定性中性回退，并复用核心锚点常量。

## 5. 非有限值与边界处理

- Android UI/桥接层应拒绝 NaN、正负无穷和硬范围外输入，并给出可理解的错误，不向引擎静默写入。
- C++ 核心防御性校验：有限但越界的数值钳制到最近边界；非有限缩放回到 1.0，非有限 X/Y/旋转回到 0.0，非法锚点回到中心 4。
- C ABI 的具体返回/钳制行为必须与本契约和单元测试一致。

## 6. 关键帧插值约束

- 旋转按未折返的角度数值线性 / 缓动插值，不采用最短角路径；例如 0° 到 1080° 的中点为 540°，必须保留用户明确设置的多圈旋转。
- 关键帧端点与插值采样结果都必须遵守同一属性硬范围。贝塞尔缓动可以产生过冲，但变换属性在 `ClipAnimation::sample()` 输出时必须钳制到对应 `PropertySpec`，不得让缩放变为零/负数，也不得让 X/Y/旋转越过边界。
- 预览与导出必须调用同一套 `ClipAnimation::sample()` 语义，禁止在某一条渲染路径另行折返旋转或采用不同范围。
- `tests/test_animation.cpp` 覆盖多圈旋转中间值、缩放上下边界过冲，以及位置/旋转过冲钳制。

## 7. 未来扩展

如需自由锚点、负缩放镜像、非等比 X/Y 缩放、像素单位位置或更大角度范围，必须先升级跨平台核心模型和项目序列化版本，再升级 C ABI 与各端 UI；不能仅扩大某一端滑块范围。
