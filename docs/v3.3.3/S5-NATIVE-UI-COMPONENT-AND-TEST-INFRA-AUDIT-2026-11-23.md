## 1. 自动字幕面板补充发现

文件：`mobile/native/android/NativeAutoSubtitlePanel.kt`

已确认：
- 面板圆角固定为 12dp，内边距 12dp，垂直间距 9dp。
- 标题 12sp，描述/状态 10sp，进度百分比 9sp，未连接说明 9sp。
- 开始/取消按钮直接使用 Material3 Button 默认尺寸，没有显式的公共最小触控尺寸、最大视觉尺寸或窄宽度布局策略。
- 描述、状态和错误消息没有在该组件内部看到明确的长文本滚动/折行策略约束。
- 面板 Column 本身没有声明宽度上限、窄屏布局模式或内部滚动；由父级传入 modifier 决定其约束。

风险：
- 系统字体放大、长错误消息、窄屏/横屏、较窄参数面板下，需要验证文本折行、按钮并排空间和整体高度。
- 9–12sp 的文字规格需要统一纳入可读性与字体缩放验收，不可假定系统 fontScale 自动解决所有布局问题。
- 默认按钮尺寸可能与应用统一触控目标和视觉尺寸系统不一致。

整改方向：
- 使用统一 Design Tokens 管理字号、间距、圆角、按钮视觉尺寸和最小触控目标。
- 面板宽度由父级布局策略提供，并设置合理约束；窄空间下按钮可换行/纵向排列。
- 长状态/错误信息允许换行或在受限高度内滚动，确保操作按钮仍可达。
- 对运行中、无进度值、错误、服务未连接、可取消等状态分别做布局回归。

## 2. 原生 UI 自动化测试基础设施缺口

本次对仓库树和 `android/app/build.gradle.kts` 检查发现：
- 当前可见 Android 本地测试依赖包含 JUnit 4.13.2 与 org.json。
- 未发现 `androidTest` 测试源集路径。
- 未发现 Compose UI Test、Espresso、Robolectric、Paparazzi 或 Roborazzi 相关测试依赖配置。
- 已有 JVM 测试集中在 Host reducer、关键帧值规则、模型路径策略、语音 PCM/PTS/重采样/取消保护、时间线快照校验等逻辑；这些测试不等同于 Compose 布局/交互/截图测试。

影响：
- 当前自动化证据可以证明部分业务规则和状态校验，但无法证明不同屏幕宽度、字体缩放、Insets、弹窗尺寸、按钮形状和间距在真实 UI 中正确。
- 仅通过 Kotlin 编译和 JVM 单测，不能将任何页面标记为响应式适配完成。

建议测试层次：
1. 纯 JVM：Design Tokens、窗口类别决策、约束计算、时间线几何配置和尺寸边界的纯函数测试。
2. Compose UI：关键页面语义节点、可见性、可点击性、文本折行、滚动和交互状态测试。
3. 视觉回归：主页、设置、创建流程、登录、自动字幕、剪辑器/时间线、参数面板在代表性窗口尺寸下的截图对比。
4. 仪器/设备测试：WindowInsets、IME、DisplayCutout、方向变化、分屏/折叠窗口和实际触控。
5. 几何断言：圆形控件宽高相等、图标不变形、最小触控边界、同类组件间距一致、组件无越界/非预期重叠。

测试矩阵需覆盖小屏竖屏、常规手机、大屏/高长宽比、窄屏横屏、平板宽窗口、fontScale 放大、IME 显示/隐藏和窗口尺寸变化。设备矩阵可以按风险分层执行，但不能只测单一默认模拟器。
