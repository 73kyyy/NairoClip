# NairoClip 全量原生 UI 响应式适配规范与验收矩阵

- 日期：2026-11-23
- 仓库：`73kyyy/NairoClip`
- 适用范围：全部正式页面、弹窗、底部面板、工具栏、控件、原生页面组件及后续新增 UI
- 性质：S5 原生 UI 迁移的全局强制设计与验收要求；不改变既有依赖 DAG、审批门或运行时入口。

## 1. 总体要求

所有页面必须按实际可用窗口空间进行响应式布局。禁止以单一机型、固定分辨率或全界面等比缩放作为适配方案。已存在的 Compose 原生页面和组件也必须重新审查并纳入整改，不能因为源码已存在就视为适配完成。

适配目标包括：布局稳定、尺寸有界、比例正确、间距一致、触控可用、内容完整、系统区域安全，以及窗口尺寸变化时状态连续。

## 2. 全量页面覆盖范围

以下范围全部适用，不因当前是否已原生化而豁免：

- 应用主框架：启动入口、首页、项目列表、导航、全局工具栏、页面容器。
- 项目流程：新建项目、导入媒体、模板选择/填充/进度、项目设置、保存与恢复提示。
- 账号与支持：我的、登录/注册、手机号验证、反馈、FAQ、帮助、法律声明、崩溃日志。
- 设置：全部设置分类、设置项、开关、选择器、权限说明、确认和错误弹窗。
- AI 功能：AI 编辑向导、参考视频分析、字幕、OCR、语音处理、降噪、超分及各功能的参数/进度/结果界面。
- 剪辑器：预览区、一级/二级工具栏、参数调节面板、素材面板、轨道头、多轨时间线、片段、关键帧、曲线编辑、字幕/文字、音频、滤镜、调色、蒙版、转场、特效、跟踪、导入导出。
- 所有二级/三级页面、对话框、菜单、Popover、Bottom Sheet、浮层、空状态、加载状态、错误状态和权限状态。
- 后续新增的任何页面与组件。

已存在的原生 UI 组件需进行尺寸、间距、比例、Insets、状态变化及交互回归；尚未迁移的页面在首次原生实现时直接遵守本规范。

## 3. 设备与窗口适配维度

必须按运行时窗口和可用空间适配，而不是按品牌或机型硬编码：

- 小屏、常规屏、大屏手机。
- 16:9、18:9、19.5:9、20:9、21:9 等不同长宽比。
- 不同分辨率、密度、系统显示大小及字体缩放。
- 竖屏、横屏及方向切换。
- 平板与自由窗口/分屏窗口。
- 折叠屏折叠、半展开、展开及窗口尺寸连续变化。
- 刘海、挖孔、圆角屏、状态栏、导航栏、手势区域和软键盘。
- 多窗口、应用窗口缩放、前后台恢复及配置变化。

窗口类别只是布局决策输入之一；具体组件还必须结合局部可用宽高和内容约束。

## 4. 组件尺寸与几何约束

### 4.1 比例约束

- 圆形按钮、圆形图标容器必须保持宽高相等，使用明确的 1:1 约束；不得由父布局分别拉伸宽高。
- 正方形缩略图或方形控件必须保持 1:1。
- 长方形按钮、卡片、预览容器按组件设计比例或内容约束布局，不得任意拉伸。
- 图标和图片保持源宽高比；禁止非等比缩放。
- 视频预览按媒体宽高比适配可用区域，按明确的 Fit/Crop 策略显示，禁止意外变形或裁切。
- 需要固定形状的组件不能依赖不受约束的 weight/fillMaxWidth/fillMaxHeight 组合产生尺寸。

### 4.2 尺寸边界

- 交互控件定义合理的最小触控尺寸和最大视觉尺寸。
- 视觉图标尺寸与触控容器尺寸分离；扩大触控区域不得拉伸图标。
- 大屏上控件不能无限增大；小屏上不能缩到难以辨认或操作。
- 文本按可用宽度布局，允许合理换行、滚动或重新编排，不得静默裁切关键内容。
- 字体使用 sp，布局尺寸使用 dp；禁止把物理像素当作跨设备尺寸单位。

### 4.3 间距与对齐

- 建立统一 Design Tokens：间距阶梯、组件高度、图标尺寸、触控尺寸、圆角、边框、字号、面板内边距。
- 同一工具栏、同类列表、同级参数组的间距与对齐规则必须一致。
- 屏幕变窄时优先滚动、换行、分组或改变布局结构，不得让相邻按钮挤压重叠。
- 屏幕变宽时限制内容最大宽度或合理分栏，不得让间距无限增长。
- 不得依赖页面各自散落的魔法数字维持视觉一致性；特殊组件需记录例外约束及理由。

## 5. 页面级响应式策略

- 小屏手机：优先保证主要任务与触控可用；次要内容可在面板内部滚动或分层展示，不得删除功能。
- 常规手机：维持既定信息层级和设计密度。
- 大屏手机：利用额外空间舒展内容，限制过宽文本和控制组。
- 高长宽比：按实际可用高度分配区域，不得出现无意义的大块空白。
- 横屏：重新评估主次区域和面板排列，不得只旋转竖屏布局。
- 平板/宽窗口：使用多栏或主内容+检查器等适合宽屏的结构，不得把手机布局整体放大。
- 折叠屏：根据折叠状态、铰链/分隔区域和窗口尺寸切换布局；状态、选中对象、播放位置和编辑上下文不得无故丢失。
- 弹窗和浮层：限制在可用窗口范围内，正确选择居中、锚定或滚动策略，不能超出屏幕。

## 6. 剪辑器专项约束

- 预览、工具栏、参数面板和时间线必须独立测量和分配空间，不能互相覆盖。
- 一级工具栏保持既定横向交互；空间不足时允许横向滚动。
- 二级工具栏必须在一级工具栏右侧同一横向区域展开；再次点击当前一级项收起，切换一级项自动切换二级项。不得擅自改为抽屉。
- 参数面板可按窗口宽度调整排列和滚动方向，但不得丢失参数、输入值或精细调节能力。
- 轨道头、轨道高度、时间刻度、片段和关键帧保持可读可操作；轨道高度不得随大屏无限放大。
- 时间线大量片段应采用可视区域虚拟化/增量更新，不能因适配而一次性创建全部昂贵 UI 节点。
- 视频预览使用适合视频渲染的 Surface/纹理承载路径；Compose 不得逐帧重绘大型视频帧。
- 横屏和平板可以调整预览与时间线占比，但必须保留关键剪辑操作和明确的空间层级。

## 7. Android 系统区域与窗口变化

- 统一处理 WindowInsets：状态栏、导航栏、显示切口、系统手势区域和 IME/软键盘。
- 采用一致的 Edge-to-Edge 策略；背景可延伸到系统区域，重要控件必须处于安全可交互区域。
- Home 手势提示条不得遮挡重要操作；不得通过永久添加大块底部空白掩盖 Insets 错误。
- 系统栏显示/隐藏、键盘弹出/收起、分屏和窗口尺寸变化时，布局不得跳动、黑边异常或丢失状态。
- 对配置变化和进程恢复分别验证；不能把保持 Compose 组合状态等同于持久化恢复。

## 8. Compose 实现约束

- 使用 Jetpack Compose 响应式布局和 Window Size Classes/窗口尺寸信息；结合局部约束决定组件尺寸。
- 建立统一 Design Tokens 与基础组件（按钮、图标按钮、输入框、卡片、面板、列表行、弹窗等），页面不得重复实现互相冲突的尺寸规则。
- 对圆形组件使用明确的等宽高约束（例如 aspectRatio(1f) 或等价约束），并确保父容器不会破坏比例。
- 避免依赖固定设备分辨率、机型判断、硬编码屏幕宽高和全局缩放因子。
- 处理字体缩放、RTL/无障碍语义、焦点顺序、键盘导航和触控目标。
- 响应窗口变化时保留业务状态；UI 状态与编辑工程持久化状态必须分层管理。
- 为每类布局保留可测试的尺寸/状态输入，避免只能靠截图人工判断。

## 9. 自动化与设备验收矩阵

每个页面及其关键状态至少覆盖：

1. 小屏手机竖屏。
2. 常规手机竖屏。
3. 大屏/高长宽比手机。
4. 手机横屏。
5. 平板/宽窗口。
6. 折叠/展开窗口状态（设备或可验证的模拟窗口环境）。
7. 系统字体与显示大小放大。
8. 键盘弹出、系统栏/手势区域变化。
9. 窗口尺寸连续变化、前后台恢复。

自动化检查至少包括：

- 圆形组件宽高相等；正方形组件比例正确。
- 图标、图片和预览无非等比拉伸。
- 组件边界无越界、非预期重叠和裁切。
- 同类控件间距、对齐和尺寸令牌一致。
- 关键触控区域满足最小尺寸。
- 关键文字在字体放大时仍可读、可访问。
- 弹窗/面板位于可用窗口内。
- 窗口变化后选中状态、输入值、播放位置和编辑上下文保持正确。

截图/视觉回归用于发现视觉偏差；布局断言、交互测试和真机测试用于确认几何与行为。CI 通过不等于真机验收通过。

## 10. 完成定义（Definition of Done）

页面只有同时满足以下条件，才可标记为“原生 UI 适配完成”：

- 已由原生组件承载正式交互，而非只有静态 Compose 页面源码。
- 真实导航、数据、业务回调、错误/加载/空状态均接通。
- 已按本规范覆盖相关窗口类别与系统 Insets。
- 关键控件比例、尺寸、间距、对齐和触控区域通过自动化检查。
- 关键路径通过交互测试与视觉回归。
- 对设备特有行为完成真机或等效设备验证，并记录设备/窗口条件和结果。
- 不存在已知的重叠、越界、意外裁切、椭圆变形、不可点击或系统栏遮挡问题。

只有源码存在、只通过 Kotlin 编译、只通过 Host/NDK CI 或只在单一模拟器截图正常，均不能标记为全量完成。

## 11. 依赖与审批边界

本规范纳入 S5 原生 UI 迁移任务，但不改变现有任务 DAG 和审批状态：

- 不因本规范授权而提前切换 Manifest/Launcher Activity。
- 不提前删除 WebView 或兼容回退路径。
- 不绕过 A-5、A-6、A-12、S1-3、S3-1、S1-8D 等既有审批和依赖门。
- 前置条件未解除时，可继续进行只读审查、规范细化、非受保护文件的测试设计与准备；不得修改受保护运行时文件。
- 本文是适配要求和验收标准，不代表任何页面已经完成适配或真机验收。

## 12. 执行原则

已原生化页面先做全量适配审计与整改；未原生化页面在迁移时直接按本规范实现；尚未接入宿主的原生组件在接线阶段同步完成适配。以页面/组件为单位记录状态、缺陷、修复提交、自动化结果和设备验收证据，避免把“已创建组件”误报为“已完成原生迁移”。
