### P-10 ⬜ 特效参数面板统一改造

**现状**：`l3-spec.js` 定义了特效清单，但参数控件是通用滑块。

**问题**：35 个特效全用同一个滑块 UI，用户不知道"这个 0.5 意味着什么"。

**方案**：为每类特效定义**语义化控件**：

| 特效 | 当前 | 应改为 |
|---|---|---|
| 高斯模糊 | 滑块 0~100 | 滑块 + "像素"单位 + 画面模糊示意 |
| 转场时长 | 滑块 | 时间输入（0.1s / 0.3s / 0.5s 快选） |
| 速度曲线 | 滑块 | 曲线编辑器（已有数据模型） |
| 暗角 | 滑块 0~1 | 滑块 + 边角预览 |

**交付**：`EffectSpec` 扩展 `unit` / `hint` / `presets` 字段。

### P-11 ⬜ 前端工程化（B0 配套）

**现状**：静态 HTML，无 `package.json`，无打包，无类型检查。

**问题**：

- `l3-panel.js` 928 行、`editor.js` 1,693 行，全是全局函数
- 无模块化，改一处怕影响别处
- 无构建，改完直接刷新，出错只能靠控制台

**方案**（保守，不引入重框架）：

1. 加 `package.json` + Vite（仅打包，不换框架）
2. ES Module 拆分：`editor.js` 按职责拆成 timeline / preview / panels / gestures
3. 加 ESLint（no-undef / no-unused）
4. 打包产物进 `dist/`，`build.gradle` 引用

**风险**：拆分可能引入回归。建议**先加 lint，再拆**。

### P-12 ⬜ 编辑器时间轴性能（B0 配套）

**现状**：`renderTracks()` 全量重绘。

### P-14 ⬜ 转场 UI 入口（**最高优先级**）

**这是所有 UI 缺口里性价比最高的一项。**

**现状（实测）**：

- 核心层：**34 种转场** + 完整校验链（`validateTransition`：时长、顺序、间隙、链式 A→B→C）
- C ABI：`nc_add_transition` 已导出
- UI：`mobile/assets/*.js` 中**唯一出现 `nc_add_transition` 的地方是 `nc-api.js` 的包装**，
  **没有任何面板或手势调用它**

结果：**用户完全无法添加转场**。花了大代价做的 34 种转场锁在柜子里。

**方案**：

1. **手势**：两个相邻片段交界处，双指捏合（或长按交界）→ 弹转场选择面板
2. **面板**：`l3-spec.js` 已有 `transpreset` / `transparam` / `transkf` 三个面板定义，
   需补充「从交界触发」的入口
3. **视觉**：已存在的转场在时间轴上显示为**交界处的 X 形标记**（可点击编辑/删除）
4. **拖拽**：从转场库拖一个转场到两片段交界处直接应用

**交互细节**：

```
片段A [========]  ← 交界 →  [========] 片段B
                       ↑
              点击出现 "+" → 选择转场
              已有时显示 "X" → 点击进参数
```

**校验提示**：间隙不足时（`available < duration`）显示"两片段间距不够，
需要先调整片段位置"，而不是静默失败。

**交付**：可在任意两相邻片段间添加/编辑/删除转场；不足条件有明确提示。

**预估**：1.5 天。

### P-15 ⬜ 二级工具栏（**缺失**）

**现状**：`10-editor.html` 仅 120 行，**只有一级工具栏（20 个按钮），没有二级工具栏**。

**问题**：一级工具栏塞了 20 个按钮，在手机竖屏上必然拥挤。专业软件的做法是：

```
一级：分类入口（媒体 / 音频 / 文字 / 特效 / 转场 / AI）
二级：分类内的具体功能
三级：具体参数面板
```

**方案**：按功能域分组

| 一级入口 | 二级内容 |
|---|---|
| **媒体** | 导入 / 素材库 / 场景检测 |
| **轨道** | 加轨道 / 图层 / 成组 / 轨道高度 |
| **编辑** | 分割 / 删除 / 复制 / 波纹删除 / 变速 |
| **画面** | 特效 / 滤镜 / 蒙版 / 调色 / 混合模式 |
| **文字** | 字幕 / 歌词 / 翻译 / TTS |
| **音频** | 音量 / 淡入淡出 / 降噪 / 变声 / 卡点 |
| **AI** | 抠像 / 深度 / 超分 / 补帧 / 参考仿剪 |
| **关键帧** | 加帧 / 缓动 / 曲线 |

**交付**：二级工具栏可横向滚动，展开后显示对应功能；点击进入已有三级面板。

**预估**：2 天。

## 四、设计约束（必须遵守）

来自 `design/spec/01-design-direction.md` 与既有实现：

1. **图标一律代码生成**（`icons.js` 的 SVG），**不引入位图资源**
2. **颜色用 CSS token**（`assets/tokens.css`），不硬编码色值
3. **深色为主**（现有 UI 全部深色）
4. **三端一致**：同一功能在 Android/iOS/桌面 UI 结构一致，只允许尺寸差异
5. **低端设备不隐藏功能**：可提示"耗时较长"，但不能把按钮藏起来
   （`COMPLIANCE.md` §3）

## 六、待你确认的 UI 决策

1. **编辑器是否支持横屏**？目前时间轴布局是按竖屏设计的，
   横屏需要重新设计轨道区与预览区比例。

2. **模板页放首页还是独立 Tab**？竞品是首页大入口。
   现有首页只有"我的草稿"，空间足够。

3. **"自动填充"要不要做**？竞品是用户逐个点导入。
   我们做智能分配（B2-2）体验更好，但算法出错时用户会困惑。
   建议：默认逐个导入，提供"自动填充"作为可选项。

4. **是否引入前端构建**（P-11）？
   现在改前端是"改文件 + 刷新"，加构建后多一步编译。
   好处是能模块化和 lint。**建议做，但要等你确认**。
